Key Design Changes vs. Current App
❌ Current Problems
  • Generic Material Design — no brand identity
  • No bottom tab navigation
  • Sterile white + cold gray palette
  • System default fonts only
  • Stats cards use excessive padding/icons
  • ProjectCard is a 3-section spreadsheet
  • ProjectDetails is 8 vertical cards
  • Loading state = "Loading..." text
  • HomeScreen is redundant dead-end
  • Inline Alert() calls everywhere
  • Tablet-first design breaks on phones
  • AcceptInvitation buries role & project info
  • BundleCompletion has no progress bars
✅ Proposed Solutions
  • Forest green brand — field research context
  • Bottom tab nav (Dashboard/Forms/Collect/Analytics/Profile)
  • Warm off-white + amber accent palette
  • Fraunces display + DM Sans body fonts
  • Compact horizontal stat pills in header
  • 3-stat block + accent bar ProjectCard
  • 2×4 tool grid in ProjectDetails
  • Skeleton screen loading states
  • HomeScreen removed — auth goes to Dashboard
  • Toast/banner notifications system
  • Phone-first Android design · tablet adaptive
  • Invitation: hero + inviter card + 2×2 stat grid
  • Bundle: color-coded progress bars per bundle
  • Tablet landscape: two-column split for DataCollection
Screen Targeting Strategy — Android-first
Primary target: Android phones in portrait mode (360–414dp wide). All layouts designed phone-first. Every element must work on a compact 360dp screen before being enhanced for larger sizes.

Tablet adaptive (≥600dp): DataCollection switches to landscape two-column split — question panel on the left, answers on the right. This is preserved from the old tablet-first design because it genuinely improves the surveying experience on a tablet. All other screens simply reflow naturally. No forced landscape lock except for DataCollection on tablets.

Large screens / foldables (≥840dp): Dashboard shows 2-column project grid. Analytics shows side-by-side charts. No special code needed — flexbox wrapping handles it.

Implementation note: Use useWindowDimensions() to detect screen width and switch layouts. Threshold: width >= 600 = tablet. Lock DataCollection to landscape on tablet using expo-screen-orientation.

Navigation Change — Stack → Bottom Tabs + Stack
Current: Single stack navigator. Every screen stacks on top. Users must back-navigate repeatedly. No persistent navigation landmarks.

Proposed: Bottom tab navigator wraps Dashboard, Forms, Collect, Analytics, Profile. Each tab has its own nested stack. Users always know where they are. Project context passes through params, not forced navigation.

Package needed: @react-navigation/bottom-tabs
